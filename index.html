Rule by rule

Policy language

Each rule has an id, allow/deny effect, action names, role names, and conditions. * matches any action or role. Roles use any-match; conditions use all-match. Paths address flat subject or resource attributes. Operators: eq, neq, in, gte, lte. Numeric comparisons reject booleans and strings; missing values never match, including neq. Equality is type-sensitive, except equivalent integer/float numbers compare equal.

Up to 50 rules, eight conditions per rule, 20 actions/roles per rule, and 20 attributes per request section. Values are null, booleans, strings up to 120 characters, or finite numbers within ±1e9. The laboratory explains decisions; it is not connected to an enforcement system.
